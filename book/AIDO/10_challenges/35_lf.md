# Challenge `LF` {#challenge-LF status=ready}

The first challenge of the *AI Driving Olympics* is "lane following" (`LF`).

In this challenge, participants submit code that allows a Duckiebot to drive on the right-hand side of the road in Duckietown without a goal point. In the current `ente` deployment, this evaluation runs in Duckiematrix on the loop map and rewards staying in-lane and making forward progress.

The challenge is designed in a way that allows for a completely \emph{reactive} algorithm design, i.e., to accomplish the challenge it is not strictly necessary to keep past observations in memory. 

In particular, intersections are not part of the active `ente` loop-map evaluation for this challenge.

## `LF` in Simulation {#challenge-aido_lf status=ready}

The active `ente` lane-following challenge is `aido-LF-sim-validation`. The canonical challenge definition lives in `challenge-aido_LF/challenges/LF-norm-vali.challenge.yaml`, and the evaluator uses protocol [`aido6_embodied_sys`](#aido6_embodied_sys).

The evaluator runs Duckiematrix on the loop map in Gym mode for up to 120 simulated seconds. The physics engine advances when the solution publishes wheel commands, so the same submission image can be used both for local evaluation and for the public `ente` deployment.

### `aido-LF-sim-validation` Details {#aido-LF-sim-validation status=ready}

- [Challenge overview](https://staging-challenges.duckietown.com/humans/challenges/aido-LF-sim-validation)
- [Leaderboard](https://staging-challenges.duckietown.com/humans/challenges/aido-LF-sim-validation/leaderboard)
- [All submissions](https://staging-challenges.duckietown.com/humans/challenges/aido-LF-sim-validation/submissions)

- Interaction protocol: [`aido6_embodied_sys`](#aido6_embodied_sys)
- Scored metrics: `survival_time`, `dist_traveled`, `intersection_count`

If you need artifact-rich debugging while iterating on your solution, run the same submission image locally with:

    $ dts challenges evaluate --challenge aido-LF-sim-validation

The public validation challenge intentionally focuses on the final evaluation metrics rather than exposing the full local debugging surface.
